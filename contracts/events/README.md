# Event contracts

Generated by `disclosure-atlas contracts` from the Pydantic models in `src/disclosure_atlas/events/contracts.py`;
do not edit by hand. CI regenerates them and fails on any difference. The publisher registers them in the schema
registry (subject `<topic>-value`, JSON Schema, BACKWARD compatibility) when `ATLAS_SCHEMA_REGISTRY_URL` is set.

| Contract | CloudEvents `type` | Topic | Key |
|---|---|---|---|
| [filing-published.v1](filing-published.v1.json) | `eu.disclosure-atlas.filing.published.v1` | `atlas.filings.v1` | issuer LEI (record id when absent) |
| [snapshot-committed.v1](snapshot-committed.v1.json) | `eu.disclosure-atlas.snapshot.committed.v1` | `atlas.snapshots.v1` | dataset |

Envelope: CloudEvents 1.0 in Kafka **binary mode**. The attributes are record headers (`ce_specversion`, `ce_id`,
`ce_source`, `ce_type`, `ce_time`, `ce_subject`, `ce_dataschema`, `content-type: application/json`) and the record
value is the JSON payload, so a consumer reads plain JSON and the registry validates exactly the payload.
`ce_id` of a filing is its record id: delivery is at-least-once and consumers deduplicate on it.

`filing-published.v1` has the same fields as the REST API's `Transaction`, so the live stream forwards it as is.
Breaking changes get a new name (`.v2`) and a new topic.
